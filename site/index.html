What you can actually do with it.

Everything below is one line typed at a prompt. No SDK, no scripting language to learn, and nothing installed on the device.

  • Set the room before doors open

    Save a working state once — every route, every label — and put it back in one go, the morning after somebody “had a quick look” at the rack.

    bmd videohub restore sunday-service.json

  • Undo whatever just happened

    Every change writes the device's previous state to disk first. There is always a file from thirty seconds ago, and it is only ever a restore away.

    Backup: …/20260829-143512.json

  • Label once, and everything agrees

    Names go onto the hardware, not into a config on your laptop. The front panel, the multiviewer, and everyone else's control app all read the same thing.

    bmd videohub input rename 3 "Lectern Cam"

  • Change a feed without walking to the rack

    From the desk, from the truck, from a laptop on the other side of the building. It is one small program and a network connection.

    bmd atem aux set 1 "Stage Wide"

  • See what changed, and when

    Watch the device live, including changes somebody else made from the front panel or another controller. Useful at the time, and more useful afterwards.

    bmd videohub watch

  • Put it on everything

    It is a 4 MB download and one file — no installer, no admin rights, nothing to keep updated on ten machines. Copy it to the gallery PC, the rack-room box with no monitor, your laptop, and change the rack from wherever you happen to be standing.

    ssh rack-room "bmd videohub route set 4 13"

  • Put it in the cue stack

    Because it is one line at a prompt, it is also one line in a cue script, a scheduled job, or a button on a stream deck — prepared in advance, like everything else in the running order.

    bmd videohub route set 7 2

Label your network well, and an AI can run it.

This is the part that surprises people. bmd was built so that a person and an AI assistant drive the same tool — and the thing that makes an assistant genuinely useful is something you control completely: what you called everything.

1

Name things the way you'd say them out loud

SDI 7 tells an assistant nothing. Lectern Cam tells it everything. Labels live on the hardware, so this is a one-off job that every device and every operator then benefits from.

2

Give the assistant the manual

One command installs everything an AI needs to know about bmd — the commands, the conventions, and the mistakes to avoid — as a skill it loads only when you are actually talking about video.

bmd agents --skill

3

Ask for what you want

It reads your labels, works out which device does what, and makes the changes — backing each one up on the way, so anything it does can be undone.

assistant 
Put the lectern camera on both foyer screens, and give the
stage monitor the wide shot. Leave the recording feed alone.
Reading labels from 2 devices…
$ bmd videohub route set 6 3    # Foyer Screen L ← Lectern Cam

$ bmd atem aux set 1 "Stage Wide"
Done. Three changes, all backed up. Recording feed on output 12
untouched.

An illustration of the shape of it, not a transcript. The assistant is whichever one you already use; bmd's part is being legible enough for it to drive — every command returns structured output, and nothing reports success it did not verify.

Download

One file, about 4 MB. No installer, no runtime, no admin rights — copy it where you want it and run it.

  • Windows (x64) bmd-win-x64.zip
  • Linux (x64) bmd-linux-x64.tar.gz
  • Linux (ARM64) bmd-linux-arm64.tar.gz
  • macOS (Intel) bmd-osx-x64.tar.gz
  • macOS (Apple Silicon) bmd-osx-arm64.tar.gz

Unzip it, put it somewhere on your PATH, and point it at a device: bmd discover --add. Checksums, the macOS first-run block and updates are all on the install page.

Find the gear on your network

Asks the local network what Blackmagic devices are out there. Add --add to pick one and remember it, so you never type its address again.

bmd discover --add
NAME                               TYPE      ADDRESS
Blackmagic Smart Videohub 40 x 40  videohub  192.168.4.100:9990
Blackmagic MultiView 4             multiview 192.168.4.96:9990
Blackmagic ATEM Television Studio  atem      192.168.4.98:9910

Point bmd at a device by hand

For when you already know the address, or discovery cannot reach it across a subnet. Remembered for your user, wherever you run it.

bmd config set videohub.host 192.168.1.50

Add --project to pin one folder to one device instead — handy when a show lives in its own directory.

Work with more than one of the same thing

Two switchers, two routers? Give each a name, then switch between them. Anything that changes a device tells you which one it acted on.

bmd atem context list
bmd atem context set gallery
   CONTEXT  HOST
*  default  192.168.4.98
   gallery  192.168.4.30

Send a source somewhere

Destination first, then source — the same order the front panel asks for. This sends input 13 to output 4.

bmd videohub route set 4 13
output 4 (FoH MV 1): FoH Sw MV → Switcher PGM
Backup: …/20260829-143512.json

Stop anyone else touching an output

Locks live on the device and are shared with every other controller, so a locked output stays locked for the front panel too. output unlock releases it.

bmd videohub output lock 4

Save the whole state to a file

Every label and every route, read back and checked against the device before the file is written. This is the file you restore from.

bmd videohub export sunday-service.json
Exported and verified: 40 inputs, 40 outputs, 40 routes → sunday-service.json

Put a saved state back

Changes only what differs, so a hub already in the right state is left alone. --dry-run shows the plan without touching anything.

bmd videohub restore sunday-service.json --dry-run

Label a source on the hardware

Writes the name to the device itself, so the front panel and every other controller agree with you. This is the groundwork that makes the AI section above work.

bmd videohub input rename 3 "Lectern Cam"

Watch changes as they happen

Including changes made from the front panel or somebody else's control app. Runs until you stop it.

bmd videohub watch
output 4 (FoH MV 1): FoH Sw MV → Switcher PGM
output 7 lock: unlocked → locked

Put a source in a multiviewer window

Destination first again: view 1 shows source 3. See the MultiView guide for overlays, solo and the rest.

bmd multiview view set 1 3

Change the multiviewer grid

The device decides what layouts it supports, not bmd — so it accepts or refuses the value and you are told which.

bmd multiview layout 2x2

Feed a stage monitor or a recorder

An auxiliary output carries any source independently of what is on air. Name the source or use its number.

bmd atem aux set 1 "Stage Wide"
Aux 1 now shows 4 (Stage Wide)

Cut to air

This one is live the instant it lands, so it asks first — and refuses outright in a script unless you pass --force. preview set changes nothing on air and does not ask.

bmd atem program set "Lectern Cam"
About to cut ATEM Television Studio HD to 3 (Lectern Cam).
This goes on air immediately.

Teach an AI assistant to use it

Installs everything an assistant needs — the commands, the conventions, and the traps — as a skill it loads only when a task actually involves video hardware. Never into your project's own instructions.

bmd agents --skill

Machine-readable output, on any command

One JSON document per command, with field names that do not change between releases. Exit codes are consistent too: 0 worked, 1 the operation failed, 2 the command was wrong.

bmd videohub route list --json
[{"output":1,"outputLabel":"Projector AR","input":1,"inputLabel":"FoH Sw PGM"}]
