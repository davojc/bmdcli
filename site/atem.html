1. Connecting

An ATEM does not speak the protocol the Videohub and MultiView share. It uses a binary protocol over UDP port 9910, with a session handshake, sequence numbers and acknowledgements. None of that is visible in use, but it does mean the port is different and the address lives under its own config prefix. 

bmd discover --add

An ATEM shows up with type atem, and picking it writes atem.host and its port. If you already know the address: 

bmd config set atem.host 192.168.1.30

More than one ATEM? Give the second one a context and switch between them. A context is just a name for a device, stored alongside the first rather than replacing it: 

bmd config set atem.host 192.168.1.31 --context gallery
bmd atem context list
bmd atem context set gallery
   CONTEXT  HOST
*  default  192.168.1.30
   gallery  192.168.1.31

The choice sticks until you change it, and every command afterwards acts on that switcher. Because that is easy to forget, anything that changes a switcher tells you which one it acted on whenever a named context is active — on stderr, so --json output is unaffected: 

(on gallery — 192.168.1.31)
Aux 1 now shows 4 (Stage)

bmd atem context set with no name lets you pick from a list, and bmd atem context set default goes back to the first one. Add --project to pin one directory to one switcher instead of changing it everywhere. Contexts work the same way for Videohubs and MultiViews.

Every bmd atem command also takes --host, --port and --timeout for one-off use. If you point it at the wrong device, it says so plainly rather than hanging — a Videohub or MultiView has nothing listening on 9910 at all: 

error: nothing is listening on 192.168.1.60:9910 (an ATEM listens on UDP 9910)

2. Sources and ids

Start by seeing what the switcher has: 

bmd atem info
Model:            ATEM Television Studio HD
Protocol:         2.30
Mix effects:      1
Sources:          24
Downstream keyers:  2
Auxiliaries:      1
Media players:    2
Video mode:       11 (raw device value)

Twenty-four sources, but only eight of them are things you can plug a cable into. The rest are internal: colour bars, colour generators, media players, key and mask signals, clean feeds, the auxiliary, and the program and preview outputs. input list shows the real inputs, which is almost always what you want: 

bmd atem input list
ID  NAME        SHORT
1   Presenter   PRES
2
3
4   Stage       STG
5   Media       MEDI
6   Lyrics      LYRC
7   Confidence  CONF
8   Stream      STRM

Blank rows are not a bug — those inputs genuinely have no name set on the switcher. That is exactly what the next section fixes.

Add --all to see everything, which is how you find the id of an internal source to route to an aux: 

bmd atem input list --all
ID     NAME              SHORT
0      Black             BLK
1      Presenter         PRES
...
1000   Color Bars        BARS
3010   Media Player 1    MP1
8001   Auxiliary 1       AUX1
10010  Live On Screens   PGM
10011  Not Live          PVW

You can give a name instead of an id anywhere a source is expected, which is usually easier than looking one up: 

bmd atem aux set 1 Stage
bmd atem preview set "Color Bars"
bmd atem input rename Lyrics "Lyrics Desk"

Long name or short name, case-insensitively. Ids still win, so a source literally named 4 can never shadow source 4.

Those ids are the switcher's own, and bmd does not renumber them. Everywhere else in bmd, numbering is 1-based to match a device's front panel. An ATEM's source ids are not a dense range — inputs are 1–8, but colour bars are 1000 and media player 1 is 3010 — so renumbering them would invent a scheme that the switcher's own software control, its front panel, and every other controller disagree with. Auxiliary outputs are counted from 1, because there the device labels them that way itself.

3. Naming inputs

A name set here is set on the switcher itself, so it shows up in its multiviewer, in ATEM Software Control, and in every other controller on the network — not just in bmd. 

bmd atem input rename 2 "Camera Two"
Renamed source 2 to 'Camera Two' (CAM2)
Backup: /home/you/.local/state/bmd/backups/192-168-1-30-atem-television-studio-hd/20260831-142530.json

Each input carries two names: a long one of up to 20 characters, and a short one of up to four. The short name is what the switcher prints on multiviewer labels, so it is the one people actually read during a show. Set them together or separately: 

bmd atem input rename 2 "Camera Two" --short CAM2
bmd atem input rename 2 --short CAM2

Naming one leaves the other alone, so tightening a short name never blanks the long one. A rename that would change nothing is reported and skipped rather than sent — it costs a write to a production switcher and buys nothing: 

No change: source 2 is already named that.

4. Auxiliary outputs

An auxiliary is an output that can carry any source independently of what is on air, which makes it the usual feed for a stage monitor, a recorder, or a presenter's confidence screen. 

bmd atem aux list
AUX  SOURCE  NAME
1    6       Lyrics

Point one at a different source by id, using input list --all to find the id: 

bmd atem aux set 1 4
Aux 1 now shows 4 (Stage)
Backup: /home/you/.local/state/bmd/backups/192-168-1-30-atem-television-studio-hd/20260831-142612.json

Auxes are numbered from 1, matching the switcher's own labels. An aux the switcher does not have is refused before anything is sent: 

error: aux must be between 1 and 1, not 2

5. Program and preview

bmd can also cut. This is deliberately the least emphasised part of the ATEM support: a switcher is usually the most production-critical device in a rack, and a command line is not where most people want to be during a show. It exists for automation — a scheduled cut to a holding slide, a scripted start-of-stream state. 

bmd atem status
Program:  6      Lyrics
Preview:  1      Presenter

preview set changes nothing on air. program set is a hard cut, on air, immediately: 

bmd atem preview set Stage
bmd atem program set Stage

program set asks before it acts, because nothing else in bmd is both instant and visible to an audience: 

About to cut ATEM Television Studio HD at 192.168.1.30 to 4 (Stage). This goes on air immediately.
Type y to continue:

In a script, or anywhere without a terminal, there is nobody to ask — so it refuses outright rather than prompting into the void or quietly proceeding. A scheduled job cuts to air only where someone wrote --force and meant it: 

error: refusing to cut to air without a terminal to confirm at (re-run with --force if that is what you mean)

preview set has no such guard, because it changes nothing on air. Both take --mix-effect for a switcher with more than one; it defaults to 1. There is no transition or auto-mix command in this release.

6. Backups

Every command that changes the switcher writes a backup of the pre-change state first, and tells you where it went. The snapshot holds what bmd can change: every source's names, the aux routing, and the program and preview buses.

It is deliberately not a full device backup. A switcher's transitions, keyers, media pool and audio mixer are outside what these commands touch, and a snapshot implying otherwise would be a promise bmd could not keep. For a complete backup, use ATEM Software Control's own save-to-file.

Backups honour backup.dir, backup.keep and backup.auto exactly as the other device groups do, and --no-backup skips one for a single command.

7. Scripting

Every command takes --json and emits exactly one document on stdout. Exit codes are the same contract as everywhere in bmd: 0 success, 1 operation failure, 2 usage error. See the Videohub guide's scripting section for the full contract. 

bmd atem input list --json | jq -r '.[] | select(.name == "") | .id'

That prints the id of every input still waiting for a name — a one-liner worth running on a switcher nobody has labelled yet.

8. What is and isn't verified

Blackmagic does not publish the ATEM network protocol. There is no equivalent of the Videohub Ethernet Protocol document, so everything here was worked out by capturing what a real switcher sends and cross-checking it against independent community reverse-engineering. That makes some of this better evidenced than others, and it is worth being straight about which is which.

  • Reading is built on real captured bytes. Every layout used to read a switcher's model, sources, names, aux routing and program/preview state was read off a capture from a real ATEM Television Studio HD III, and is tested against those exact bytes.
  • Writing was settled by experiment, on hardware. A capture only contains what the switcher sent, so no capture can confirm a command. Each command was instead sent to a real switcher in several candidate shapes, and the one it acted on is the one bmd uses. Renaming an input, routing an aux, and setting program and preview have all been run against a real ATEM and confirmed by the device's own reported state.
  • bmd never reports a change it did not see confirmed. This protocol has no way of saying no: a switcher that does not understand a command simply ignores it. So every command is followed by a wait for the device to report the new state back, and silence is treated as failure — you get did not report the change rather than a success nobody checked. That is what caught the one command whose layout was initially wrong.
  • Two switcher models, both working. Everything here was verified against an ATEM Television Studio HD III and an ATEM 1 M/E Production Studio 4K — 24 sources and one auxiliary against 31 sources and three. Both report protocol 2.30 and both accept every command unchanged, so these commands are not tied to a particular model or firmware. bmd reads each switcher's own reported capabilities rather than assuming any of them, but a model very different from those two may still behave in ways this has not seen.
  • Video mode is shown as a raw number. The mode-number-to-format table is not published, and printing a confidently wrong 1080i5994 would be worse than printing the number the device reported.
  • There is no restore, export or watch for ATEM yet, and no transitions, keyers, media player or audio control. Backups are written but must currently be read back by hand.
