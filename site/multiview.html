1. Connecting

A MultiView speaks the same protocol as a Videohub, over the same TCP port, so connecting to one works exactly the same way. The easiest way to get an address is to ask the network: 

bmd discover --add

This lists the recognized Blackmagic devices it hears on the local network and lets you pick one from a numbered list — a MultiView shows up with type multiview, right alongside any Videohubs on the same segment. Picking one writes its address (and port, if not the default 9990) into config, under the multiview. prefix rather than videohub., so the two device types never collide in the same config file.

If you already know the address — or discovery can't reach the device — set it directly: 

bmd config set multiview.host 192.168.1.60

Every bmd multiview command also accepts its own --host, --port, and --timeout, which is convenient for one-off use against a unit you haven't configured at all. See the Videohub guide's connecting section for how config layering (local .bmdconfig, global config, command-line flag) works — it's identical here.

2. Sources and views

A MultiView takes several video sources in and shows them as small windows on one big output — that output is what bmd calls a view. Every number bmd shows you is 1-based, matching the numbering on the device's own front panel. 

bmd multiview info
Model:          Blackmagic MultiView 4
Protocol:       2.8
Inputs:         8
Views:          6
Layout:         2x2
Output format:  1080i5994
bmd multiview input list
N   LABEL
1   Camera 1
2   Camera 2
3   Switcher PGM
4   Switcher PVW
…
bmd multiview view list
VIEW  LABEL       IN  SOURCE        LOCK
1     Window 1    1   Camera 1      unlocked
2     Window 2    2   Camera 2      unlocked
3     Window 3    3   Switcher PGM  unlocked
4     Window 4    4   Switcher PVW  unlocked
5     Solo        1   Camera 1      unlocked
6     Audio       1   Camera 1      unlocked

On a MultiView 4, that last part is worth stating plainly: views 5 and 6 are not windows at all. They are Solo Input (what's shown full-screen when solo mode is on — see Solo below) and Audio Input, named here the way the device labels them so this page matches what view list prints. Only views 1–4 are the actual quad-split windows on the multiview display. bmd numbers all six the same way the device does, so view list shows every one of them, but a script that assumes "view" always means "window" will be surprised on this model.

3. Routing

To put a source in a view, name the view first, then the source:

bmd multiview view set <view> <input>

For example, bmd multiview view set 1 3 puts source 3 in view 1 — destination first, then source, the same convention as videohub route set. Both numbers are 1-based and validated against the device's real source/view count before anything is sent.

Renaming a source or a view works the same way, with the new label as the last argument:

bmd multiview input rename <input> <label>
bmd multiview view rename <view> <label>

Locking a view stops other controllers from changing its source (or taking the lock from you) without --force:

bmd multiview view lock <view>
bmd multiview view unlock <view>
bmd multiview view unlock <view> --force

All of this behaves exactly like the equivalent Videohub commands — see the Videohub guide's changing routes section for the details on labels, locks, and what a rejection looks like.

4. Layout and format

Two more properties live on the device rather than per-view: the window layout, and the output video format.

bmd multiview layout 2x2
bmd multiview format 1080i5994

bmd does not validate either value. Blackmagic does not document this protocol block, and which layouts and formats are actually valid differs by MultiView model and firmware — bmd has no table to check against, so it sends whatever you give it and the device decides. 2x2 and 1080i5994 above are examples observed against a real MultiView 4, not an exhaustive list of what your unit accepts. If the device rejects a value, bmd reports what it said rather than guessing at a friendlier message: 

error: device rejected CONFIGURATION (Layout: 9x9)

Trial and error against the actual unit — or its manual, if Blackmagic's documents the block for your model — is the only reliable way to know what it accepts.

Which is why there is a way to ask your own device what it reports. config prints the whole block exactly as the device sent it, including properties bmd has never heard of: 

bmd multiview config
SETTING               VALUE
Layout                2x2
Output format         1080i5994
Solo enabled          false
Widescreen SD enabled true
Display border        true
Display labels        true
Display audio meters  false
Display SDI tally     false
Take Mode             true

On a MultiView 16, or a firmware newer than this page, that list may well be longer. bmd shows whatever arrives rather than only the settings it has commands for, so this is the honest starting point for finding out what your unit supports. Add --json to get the same thing as name/value pairs.

5. Overlays and behaviour

Four on-screen overlays can each be turned on or off independently:

bmd multiview show borders on
bmd multiview show labels on
bmd multiview show audio-meters on
bmd multiview show tally on

The setting name comes first, then on or off. Two more standalone toggles round out the device's behaviour:

bmd multiview take-mode on
bmd multiview widescreen-sd on

Take mode holds a requested change until it's confirmed rather than cutting immediately; widescreen SD only affects how standard-definition sources are displayed. Unlike layout and format, bmd does validate these: the value must be exactly on or off, since that much is unambiguous regardless of model or firmware.

6. Solo

Solo shows one source full-screen, fed from the view the device labels Solo Input, instead of the usual quad-split: 

bmd multiview solo 3
bmd multiview solo off

Giving a source number both points Solo Input at that source and enables solo mode; off leaves solo mode and does not otherwise change any routing. bmd routes the source before enabling solo, so by the time solo mode is on, the right picture is already showing rather than a moment of whatever was there before.

7. Backups, export and restore

Every command that changes the device — view set, the two rename commands, view lock/unlock, layout, format, solo, show, take-mode, widescreen-sd, and restore — snapshots the device first and reports where the snapshot went, the same way bmd videohub does. See the Videohub guide's backups section for where those files live and the backup.* config keys that control them.

export and restore work the same way too, with one MultiView-specific difference: the snapshot also captures the device's configuration — layout, output format, and every overlay/behaviour toggle — alongside labels and routing, since that's state a MultiView has and a plain router doesn't. 

bmd multiview export before.json
bmd multiview restore before.json --dry-run
bmd multiview restore before.json

As with videohub restore, --dry-run shows what would change without touching the device, and restore only ever changes what actually differs — a snapshot taken before configuration was captured (an older Videohub-era file, or one from a plain videohub export) simply leaves configuration untouched on restore. See the Videohub guide's event workflow section for the rest of the behaviour: verification on export, and safe re-running on a failed restore.

8. Watching

Like a Videohub, a MultiView can be changed by other controllers at any time — watch streams every change as it happens, no matter who made it: 

bmd multiview watch
view 1: Camera 1 → Camera 2
view 3 label: 'Window 3' → 'PGM Preview'
view 5 lock: unlocked → owned

It runs until you stop it with Ctrl+C, or the connection drops, and (like every command) accepts --json — see the Videohub guide's scripting and agents section for the JSON Lines shape and the exit-code contract, both identical here.
